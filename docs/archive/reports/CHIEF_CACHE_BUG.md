# OVERCHARGE — Browser Cache Bug: GitHub Save Feature Not Firing

**Date:** 2026-09-28
**Reported by:** Aki
**Severity:** Blocker — the new GitHub API save feature is deployed but invisible to users

---

## What's broken

Clicking SAVE in the Builder shows:

> ⚠ No save folder set — SAVE will DOWNLOAD to Downloads, not write to your Git clone

That message lives in the **old** save handler, which ran before the GitHub API publish feature existed. The new code (token-first SAVE, `pushLevelToGitHub`) is deployed to `agent/orcha-gameplay` and confirmed present on the raw GitHub CDN. The browser is not running it. It is running a cached copy of `editor/main.js` from before the fix.

Confirmed:
- `localStorage.getItem('overcharge_gh_pat')` returns the token (user has it stored)
- Raw source at `raw.githubusercontent.com/kiotdstudios/overcharge/agent/orcha-gameplay/editor/main.js` contains `pushLevelToGitHub` and `getGitHubPat`
- The running page does NOT contain those strings — it's a cached version

Workaround (for the user right now): DevTools → Network tab → check **Disable cache** → hard reload (`Ctrl+Shift+R`).

---

## Root cause

`editor.html` imports `main.js` as an ES module with no version fingerprint:

```html
<script type="module" src="editor/main.js"></script>
```

GitHub Pages does not add `Cache-Control: no-cache` headers for HTML subresources by default. Browsers (especially Chrome) cache the JS module aggressively. When we push a new `main.js`, the HTML still requests the old URL — no query string change, no hash — so the browser serves the stale cached file.

`Ctrl+Shift+R` (hard reload) bypasses the page cache but does NOT always bypass the module cache in Chrome. A URL change is the only guaranteed fix.

---

## The fix

Add a build timestamp or commit SHA as a query string to the `main.js` import in `editor.html`. The browser treats a different URL as a new resource and fetches it fresh.

### Option A — Manual timestamp (simplest, no build step)

In `editor.html`, change:

```html
<script type="module" src="editor/main.js"></script>
```

to:

```html
<script type="module" src="editor/main.js?v=20260928"></script>
```

Bump `?v=` every time `main.js` or a major dependency changes. Simple, zero tooling, just discipline.

### Option B — `buildinfo.js` auto-stamp (recommended)

We already have `editor/buildinfo.js` (generated by the builder workflow) that exports `BUILD_HASH` and `BUILD_DATE`. Use it:

```html
<!-- editor.html — replace the static script tag -->
<script type="module">
  import { BUILD_HASH } from './editor/buildinfo.js';
  const s = document.createElement('script');
  s.type = 'module';
  s.src = `editor/main.js?v=${BUILD_HASH}`;
  document.head.appendChild(s);
</script>
```

Or regenerate `buildinfo.js` as part of the GitHub Pages deploy step (a one-line GitHub Action) and reference it directly in the import URL.

### Option C — GitHub Pages `Cache-Control` header override

Add a `_headers` file (Netlify/Cloudflare Pages) or a `vercel.json` to set `Cache-Control: no-store` on `*.js` files. GitHub Pages does NOT support custom headers natively — so this only applies if the deploy target changes.

**Recommendation:** Do Option A immediately (one-line change, zero risk), then wire up Option B when there's time to add a deploy step.
